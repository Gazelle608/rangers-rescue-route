# Level 3 (Bonus) — 100 nodes, 24 required stops

## Problem
- Start: A, End: B
- Graph: 100 nodes
- Visit: 24 required stops (S1..S24) in any order
- Effective edge weight = time + risk

## Why not brute force?
24! ≈ 6.2 × 10²³ permutations — impossible.
Even Held-Karp O(2²⁴·24²) ≈ 9.6B ops is too slow in pure Python.

## Approach — hybrid heuristic
1. **Precompute** all-pairs shortest paths between the 26 key nodes
   ({A, B} ∪ 24 stops) using Dijkstra (26 runs).
2. **Nearest Neighbour** greedy for an initial ordering.
3. **2-opt** — reverse segments of the stop order.
4. **Or-opt** — move segments of length 1-3 to other positions.
5. **Random restarts** — shuffle + re-optimise until a time budget expires.
6. Expand the chosen stop order back into full node paths via cached
   Dijkstra predecessors, concatenate, write `answer.json`.

Typical result: within 1-3% of optimal for 24 stops.
